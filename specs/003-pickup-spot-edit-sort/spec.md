# Feature Specification: 自取點編輯與排序 (Pickup Spot Edit & Sorting)

**Feature Branch**: `003-pickup-spot-edit-sort`

**Created**: 2026-06-29

**Status**: Draft

**Input**: User description: "自取點管理 功能修改：新增編輯（僅限 township）、新增排序（同縣市內、以縣市分組、拖拉把手、樂觀即時儲存），既有功能不受影響。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同縣市內拖拉排序地點 (Priority: P1)

管理員在自取點管理頁進入「排序模式」，清單以縣市分組顯示。管理員以拖拉把手在同一縣市群組內調整地點（township）的先後順序，放開後該縣市的新順序立即儲存；重新整理或下次登入仍維持。

**Why this priority**: 這是本次修改的核心新價值——讓管理員自訂同縣市內地點的呈現順序。沒有它，其餘需求價值有限。

**Independent Test**: 在某縣市群組內拖動任一地點到新位置，放開後重新整理頁面，該縣市順序仍正確，即可驗證。

**Acceptance Scenarios**:

1. **Given** 某縣市底下有多個地點, **When** 管理員在排序模式下以拖拉把手把某地點拖到同縣市群組內的另一位置並放開, **Then** 該縣市群組立即以新順序呈現且順序被永久儲存。
2. **Given** 已調整過某縣市的地點順序, **When** 管理員重新整理或重新登入, **Then** 該縣市仍以先前儲存的順序顯示。
3. **Given** 一次拖放儲存過程中發生錯誤, **When** 儲存失敗, **Then** 系統提示失敗且該縣市順序回復到拖拉前的狀態（樂觀更新還原，不留下半套順序）。
4. **Given** 管理員嘗試把某地點拖出其所屬縣市群組, **When** 拖到別的縣市群組, **Then** 系統不接受此移動，地點仍留在原縣市。

---

### User Story 2 - 編輯地點名稱 (Priority: P2)

管理員可編輯既有自取點的地點（township）名稱；所屬縣市（city）不可更改。

**Why this priority**: 修正打字錯誤或調整地點描述是常見維運需求，但不阻礙排序核心價值，故次於 P1。

**Independent Test**: 對任一自取點開啟編輯，修改 township 後儲存，列表即顯示新名稱，且縣市欄位不可被更動。

**Acceptance Scenarios**:

1. **Given** 一筆既有自取點, **When** 管理員開啟編輯、修改地點名稱並儲存, **Then** 列表更新為新地點名稱，縣市維持不變。
2. **Given** 編輯介面, **When** 管理員檢視縣市欄位, **Then** 縣市為唯讀／不可編輯。
3. **Given** 同一縣市已存在某地點名稱, **When** 管理員把另一筆地點改成與其相同的名稱, **Then** 系統拒絕並提示重複（同縣市內地點名稱不可重複）。

---

### User Story 3 - 新增與既有資料的初始排序位置 (Priority: P3)

新增自取點時，該點自動排在其所屬縣市群組的最後；功能上線時，所有既有自取點都取得確定的初始順序。

**Why this priority**: 確保新點有可預期的初始位置、既有資料有確定順序；屬一次性與邊界保障，優先序最低但不可省略。

**Independent Test**: 在某縣市新增一筆自取點，確認它出現在該縣市群組最末；在含既有資料上啟用功能，確認每筆都有確定且穩定的順序、清單完整無遺漏。

**Acceptance Scenarios**:

1. **Given** 某縣市已有 N 個地點, **When** 管理員在該縣市新增一個自取點, **Then** 新自取點出現在該縣市群組第 N+1（最後）位置。
2. **Given** 功能上線前已存在的自取點, **When** 功能上線, **Then** 每筆自取點在其縣市群組內都被指派確定的初始順序（以既有建立順序為基準），無遺漏、無重複。

---

### Edge Cases

- 某縣市群組僅有一個地點時，拖拉不應出錯，亦無順序可改。
- 一般模式下若搜尋只命中部分縣市的部分地點，**不可在此狀態拖拉排序**；進入排序模式必須先清空搜尋並關閉分頁，看到完整未過濾清單。
- 兩位管理員同時調整同一縣市順序時，以最後一次儲存為準（後寫覆蓋）。
- 拖拉過程中某地點被刪除：儲存時以當下實際存在的地點為準，已不存在者略過。
- 編輯把 township 改成空白或全為空白字元時，應被拒絕（與新增的必填規則一致）。
- 排序模式進行中按「完成排序」：恢復一般模式（搜尋、分頁、操作欄），不遺失已儲存的順序。

## Requirements *(mandatory)*

### Functional Requirements

**編輯（僅限地點名稱）**

- **FR-001**: 系統 MUST 讓管理員編輯既有自取點的地點（township）名稱。
- **FR-002**: 系統 MUST 禁止透過編輯更改自取點所屬縣市（city 為唯讀）。
- **FR-003**: 系統 MUST 拒絕把地點名稱改為同一縣市內已存在的名稱（同縣市內地點名稱唯一），並提示管理員。
- **FR-004**: 系統 MUST 拒絕空白／全空白字元的地點名稱（與新增規則一致）。

**排序模式與分組**

- **FR-005**: 系統 MUST 提供「排序」按鈕以進入排序模式，並提供「完成排序」退出回到一般模式。
- **FR-006**: 系統 MUST 在清單中以縣市分組顯示自取點。
- **FR-007**: 系統 MUST 僅允許在同一縣市群組內拖拉調整地點先後順序，且 MUST 禁止把地點拖到其他縣市群組。
- **FR-008**: 系統 MUST 維持縣市群組之間的固定順序（沿用既定的縣市排列），且 MUST NOT 開放手動調整縣市之間的順序；可自訂的僅為「群組內地點順序」。
- **FR-009**: 系統 MUST 在進入排序模式時自動清空搜尋條件並關閉分頁，呈現完整未過濾的清單。
- **FR-010**: 系統 MUST 在排序模式下隱藏「操作」欄（含刪除鈕），並於每列顯示拖拉把手，且 MUST 僅在按住把手時才能拖動該列。
- **FR-011**: 系統 MUST 在退出排序模式時恢復一般模式的搜尋、分頁與操作欄。

**儲存行為**

- **FR-012**: 系統 MUST 在每次拖放完成時立即儲存「該縣市」的新順序。
- **FR-013**: 系統 MUST 採樂觀更新：先更新畫面，儲存成功則維持，儲存失敗則還原為拖拉前順序並提示錯誤。
- **FR-014**: 單次某縣市的順序儲存 MUST 為全有或全無（atomic），部分失敗時不得留下半套順序。
- **FR-015**: 系統 MUST 永久儲存調整後的順序，使其在重新整理、重新登入後仍維持。

**新增與既有資料**

- **FR-016**: 系統 MUST 將新增的自取點排在其所屬縣市群組的最後。
- **FR-017**: 系統 MUST 在功能上線時為所有既有自取點，於各自縣市群組內回填確定且唯一的初始順序（以既有建立順序為基準），無遺漏、無重複。

**既有功能不受影響**

- **FR-018**: 一般模式的搜尋、新增、刪除、分頁 MUST 維持原有行為不變。
- **FR-019**: 系統 MUST 在一般模式與排序模式之外的所有列表呈現位置，皆依「縣市固定順序 + 群組內自訂順序」呈現。

### Key Entities *(include if feature involves data)*

- **自取點 (Pickup Spot)**: 既有實體，含「縣市 (city)」與「地點 (township)」。新增一個「群組內顯示順序」屬性，代表該地點在其所屬縣市群組內的相對位置。順序在同一縣市內可比較且唯一；不同縣市之間互不影響。縣市之間的群組順序由既定固定序決定，非由管理者自訂。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員在某縣市群組內拖放調整順序後，於 1 秒內看到新順序，且重新整理後 100% 維持。
- **SC-002**: 拖拉 100% 受限於同一縣市群組內，無法把任一地點移動到其他縣市。
- **SC-003**: 排序儲存失敗時，該縣市順序 100% 回復到操作前狀態，無半套狀態殘留，且管理員看到失敗提示。
- **SC-004**: 功能上線後，100% 既有自取點在其縣市群組內具備確定的初始順序，清單無遺漏、無重複。
- **SC-005**: 新增的自取點 100% 出現在其所屬縣市群組最末。
- **SC-006**: 編輯僅能變更地點名稱，縣市 100% 不可被更動；同縣市重複名稱 100% 被拒絕。
- **SC-007**: 進入排序模式時，搜尋 100% 被清空且分頁 100% 關閉，呈現完整清單。

## Assumptions

- **縣市群組的固定順序**沿用專案既有的台灣行政區順序（即 `TAIWAN_LOCATIONS` 縣市清單的順序，同新增表單縣市下拉的排列）。此為預設假設；若需改為純字母／注音排序可再調整。
- 排序為**每縣市各自一條順序**（群組內排序），非全域單一清單；不同縣市的順序互不影響。
- 排序與編輯皆為管理端功能；顧客端的實際呈現由外部顧客 App 負責（不在本 repo 範圍），但其可讀取本系統儲存的縣市內順序。
- 低併發情境（少數管理員），併發衝突以後寫覆蓋處理即可，無需鎖定或版本控管。
- 既有自取點的初始順序以目前的建立先後（識別碼遞增）為基準，於各縣市群組內分別回填。
- 「地點名稱唯一」的範圍維持既有的（縣市, 地點）唯一性約束；編輯與新增皆受其約束。
- 排序模式的互動沿用商品排序頁（`001-product-sorting`）既有模式：拖拉把手、樂觀更新、進入時清搜尋與分頁。
