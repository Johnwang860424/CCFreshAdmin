# Quickstart 驗證指南: 後台新增訂單與來源標籤

驗證本功能端到端可運作。實作細節見 `data-model.md`、`contracts/orders-api.md`。

## 前置

1. 套用 schema 變更（在 Neon SQL Editor 執行 `db/migrations/002_add_order_tag.sql` 內容）：
   ```sql
   ALTER TABLE orders ADD COLUMN tag TEXT NOT NULL DEFAULT '網站';
   ```
2. 確認資料庫已有至少一個取貨點與數個商品（其中至少一個帶促銷，供驗證折扣）。
3. `npm run dev`，以允許清單內的 Google 帳號登入後台。

## 驗證情境

### S1 — 建立自取訂單（核心，US1）
1. 進入「訂單管理」頁，點「新增訂單」。
2. 填客戶姓名、選「自取」與一個取貨點、加入 2 項商品（其一帶促銷、數量 ≥ 2）、選來源「Line」、送出。
3. **預期**：建立成功；於該取貨點所屬縣市/地點查得此訂單；展開可見明細；總額 = 各明細折後小計加總；帶促銷品項小計符合 `calcLineSubtotal`；此訂單有取貨號碼牌；清單「來源」欄顯示「Line」。

### S2 — 建立宅配訂單（US1）
1. 「新增訂單」→ 選「宅配」、填宅配地址、加入 1 項商品、來源保留預設、送出。
2. **預期**：建立成功；於「宅配」分組查得；取貨號為「-」；來源顯示「網站」。

### S3 — 來源標籤（US2）
1. 各建立一筆來源「FB」與「Line」的訂單。
2. **預期**：清單分別顯示「FB」「Line」標籤。
3. 檢視一筆顧客端（外部）既有訂單或預設訂單。**預期**：來源顯示「網站」。

### S4 — 驗證攔截（US1 邊界）
逐一嘗試並確認皆被擋下且有提示、且未產生半筆資料：
- 不填客戶姓名送出 → 擋下。
- 不加任何商品送出 → 擋下。
- 商品數量填 0 或負數 → 擋下。
- 選「宅配」但不填地址 → 擋下。
- （可選）系統無取貨點時選「自取」→ 提示先建立取貨點。

### S5 — 原子性
1. （手動）模擬明細寫入失敗（例如暫時把某商品自 DB 刪除後送出含該商品的訂單）。
2. **預期**：整筆建立失敗，`orders` 不留下無明細的孤兒訂單。

### S6 — 結單 CSV 含來源
1. 對含上述新增訂單的分組執行「結單（依分組匯出並清除）」。
2. **預期**：下載的 CSV 含「來源」欄，各列值正確（網站/FB/Line）。
