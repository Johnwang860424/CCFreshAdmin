# Quickstart: 新增訂單重複下單警示 — 驗證指南

**Plan**: [plan.md](./plan.md) | **Contract**: [contracts/duplicate-order-check.md](./contracts/duplicate-order-check.md)

## 前置

1. `.env.local` 齊備（`DATABASE_URL`、Auth、Cloudinary——同專案 README/`.env.local.example`）。
2. `npm run dev`，以 `ALLOWED_EMAILS` 內帳號登入。
3. 準備資料：至少一條路線 R1（含取貨點 S1、S2）、一個未分路線取貨點 S3、若干上架商品。

## 驗證情境

### 1. 同路線同名 → 警示（US1-AS1、AS2）

1. 於訂單管理用「新增訂單」替「王小明」在 S1 建一筆訂單（無警示，直接成立）。
2. 再替「王小明」在 **S2**（同路線 R1）新增訂單並送出。
3. **預期**：出現確認視窗，內容逐字為「系統偵測到您可能已有訂單。請確認是否為重複下單」；此時訂單尚未建立（列表無新列）。
4. 按「仍要建立」。**預期**：訂單成立，成功訊息、取貨號視窗、列表刷新與一般新增完全相同。

### 2. 取消 → 表單保留（US1-AS3）

1. 重複情境 1 觸發警示，改按「取消」。
2. **預期**：確認窗關閉、不建立訂單；新增訂單表單仍開啟且欄位內容全數保留，可修改後重送。

### 3. 無同名 → 零額外步驟（US1-AS4）

- 以「李小華」在 R1 新增訂單。**預期**：無任何跳窗，直接成立。

### 4. 跨分組不警示（US1-AS5）

- 「王小明」已有 R1 訂單；在**另一條路線** R2 的取貨點替「王小明」新增。**預期**：無警示。

### 5. 頭尾空白視為同名（US1-AS6）

- 同分組已有「王小明」訂單；以頭尾帶空白的「 王小明 」在同分組新增。**預期**：輸入端 trim 後視為同名，出現警示。（資料庫姓名由各寫入端保證已 trim，查詢以完全相符比對。）

### 6. 宅配／未分路線分組（US1-AS7）

- 宅配已有「王小明」訂單 → 新增宅配「王小明」訂單。**預期**：警示。
- S3（未分路線）已有「王小明」訂單 → 以另一未分路線取貨點新增「王小明」。**預期**：警示。
- 宅配有「王小明」但 R1 沒有 → 在 R1 新增「王小明」。**預期**：不警示。

### 7. 多筆同名仍只警示一次（US1-AS8）

- 同分組已有「王小明」訂單 2 筆 → 再新增第 3 筆。**預期**：只出現一次確認窗，確認後只建立這一筆。

### 8. 確認後的下游錯誤照舊

- 觸發警示後按「仍要建立」，但訂單內含庫存不足的商品。**預期**：顯示既有庫存不足錯誤訊息（400），不建立訂單。

## API 層抽查（選用）

以登入 session 的 cookie 直接 POST `/api/orders`：

- 同分組同名、未帶旗標 → `409`，body 含 `requiresConfirmation: true`、`duplicateCount ≥ 1`、`error` 為指定文字。
- 同 body 加 `"confirmDuplicate": true` → `200 { success: true, ... }`。

## 收尾檢查

- `npm run lint` 通過。
- `npm run build` 通過（TS strict）。
- 409 路徑不觸發商品快取革除（伺服器 log 無 revalidate；僅建立成功時有）。
