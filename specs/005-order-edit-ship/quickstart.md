# Quickstart / 手動驗證：訂單修改、刪除與出貨/CSV 分離

無測試框架，改動以下列手動流程驗證，並以 `npm run lint` 與 `npm run build` 把關型別與規則。

## 前置

- `.env.local` 已含 `DATABASE_URL` 等（見 `.env.local.example`），可連上 Neon。
- 已登入（allowlist 內帳號）。
- 資料庫中至少有：1 條路線、1 個取貨點、數個商品（其中一個帶促銷），以及數筆訂單（可用頁面「新增訂單」建立）。
- **無 migration**：本功能不改 schema，無需執行 DB script。

## 啟動

```bash
npm run dev
```

開啟 `http://localhost:3000/orders`，於路線下拉選一分組載入訂單清單。

## 驗證 1 — 修改訂單品項（US1 / FR-001..010）

1. 對一筆含 2 項明細的訂單按「編輯」→ 開啟編輯視窗，帶入現有明細與數量。
2. 新增一項商品（數量 1）、把既有某項數量由 1 改 3、移除另一項 → 儲存。
3. **預期**：清單展開該訂單顯示更新後明細；`總額` = 各明細小計加總；改量的既有明細小計依其**原快照**（單價/促銷）重算；新增明細用**商品現價**。
4. 邊界：把某明細數量清為 0/空 → 儲存被擋，提示需正整數；移除到 0 項 → 儲存被擋，提示改用刪除。

## 驗證 2 — 刪除單筆訂單（US2 / FR-011..013）

1. 對清單某筆按「刪除」→ 出現二次確認 → 取消：訂單不變。
2. 再按「刪除」→ 確認：該筆自清單消失，其他筆數不變。
3. 重新載入頁面 → 該訂單與其明細皆不存在。

## 驗證 3 — 出貨與匯出 CSV 分離（US3 / FR-014..018）

1. 對某分組按「匯出 CSV」→ 取得 `orders_<分組>_<日期>.csv`；**訂單清單筆數不變**；再按一次可重複匯出，內容一致。
2. CSV 欄位為：取貨號、客戶姓名、來源、取貨地點、購買清單、訂單總額、電話、備註。
3. 按「出貨」（原「結單」按鈕更名）→ 顯示不可復原確認 → 確認：該分組訂單全部清除，**過程未觸發任何檔案下載**。
4. 空分組：不提供可執行出貨／匯出，或執行時提示無資料。

## 通過準則（對應 Success Criteria）

- SC-001/002：追加品項於 60 秒內完成且總額正確，需求反映在同一筆訂單。
- SC-003：可不清資料取得 CSV，且可重複匯出得一致內容。
- SC-004：出貨不下載、匯出不清資料，兩動作互不觸發。
- SC-005：修改／刪除後重載清單一致，無殘留、無誤刪。
