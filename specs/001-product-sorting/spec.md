# Feature Specification: 商品排序功能 (Product Sorting)

**Feature Branch**: `001-product-sorting`

**Created**: 2026-06-28

**Status**: Draft

**Input**: User description: "商品新增排序功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 拖拉排序商品 (Priority: P1)

管理員在商品管理頁，以拖拉的方式調整商品的顯示順序，放開後順序即被儲存，重新整理或下次登入仍維持。

**Why this priority**: 這是本功能的核心價值——讓管理員自訂商品呈現順序。沒有它，其餘需求都無意義。

**Independent Test**: 在商品列表拖動任一商品到新位置，重新整理頁面後該順序仍正確，即可驗證。

**Acceptance Scenarios**:

1. **Given** 商品列表有多筆商品, **When** 管理員將某商品拖到另一位置並放開, **Then** 列表立即以新順序呈現且順序被永久儲存。
2. **Given** 已調整過順序, **When** 管理員重新整理或重新登入, **Then** 列表仍以先前儲存的順序顯示。
3. **Given** 一次拖拉儲存過程中發生錯誤, **When** 儲存失敗, **Then** 系統提示失敗且列表回復到拖拉前的順序（不留下半套順序）。

---

### User Story 2 - 新商品排在尾端 (Priority: P2)

新增商品時，該商品自動排在現有順序的最後，管理員可再拖拉調整。

**Why this priority**: 確保新商品有明確且可預期的初始位置，避免插入位置不確定造成混亂。

**Independent Test**: 新增一筆商品，確認它出現在列表最末，且可被拖拉到他處。

**Acceptance Scenarios**:

1. **Given** 已有 N 筆商品, **When** 管理員新增一筆商品, **Then** 新商品出現在列表第 N+1（最後）位置。

---

### User Story 3 - 既有商品的初始順序 (Priority: P3)

功能上線後，所有既有商品都需具備一個確定的初始順序，不得出現順序未定義或商品消失的情況。

**Why this priority**: 保障導入時的資料正確性；屬一次性遷移，故優先序最低但不可省略。

**Independent Test**: 在含既有商品的資料上啟用功能，確認每筆商品都有確定且穩定的排序，列表完整無遺漏。

**Acceptance Scenarios**:

1. **Given** 啟用前已存在的商品, **When** 功能上線, **Then** 每筆商品都被指派一個確定的初始順序（以既有建立順序為基準），且無任何商品遺失或重複。

---

### Edge Cases

- 列表為空或僅一筆商品時，拖拉不應出錯，亦無順序可改。
- 兩位管理員同時調整順序時，以最後一次儲存為準（後寫覆蓋）。
- 拖拉過程中某商品被刪除：儲存時以當下實際存在的商品為準，已不存在者略過。
- 商品數量很多時（跨分頁），拖拉需能涵蓋完整清單，而非僅限當前可見頁。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 讓管理員以拖拉方式調整商品於列表中的顯示順序。
- **FR-002**: 系統 MUST 永久儲存調整後的順序，使其在重新整理、重新登入後仍維持。
- **FR-003**: 系統 MUST 將新增商品排在現有順序的最後。
- **FR-004**: 系統 MUST 在功能上線時，為所有既有商品回填一個確定且唯一的初始順序（以既有建立順序為基準）。
- **FR-005**: 系統 MUST 在管理端顯示商品列表的所有位置，皆依儲存的順序呈現。
- **FR-006**: 系統 MUST 在商品被刪除後，維持其餘商品既有的相對順序。
- **FR-007**: 單次排序儲存 MUST 為全有或全無（atomic）——部分失敗時不得留下半套順序。
- **FR-008**: 系統 MUST 在排序儲存失敗時提示管理員，並讓列表回復到操作前狀態。

### Key Entities *(include if feature involves data)*

- **商品 (Product)**: 既有實體，新增一個「顯示順序」屬性，代表其在商品列表中的相對位置。順序在所有商品間為全域唯一、可比較。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員拖拉調整順序後，於 1 秒內看到新順序，且重新整理後 100% 維持。
- **SC-002**: 功能上線後，100% 既有商品具備確定的初始順序，列表無遺漏、無重複。
- **SC-003**: 新增的商品 100% 出現在列表最末。
- **SC-004**: 排序儲存失敗時，列表 100% 回復到操作前順序，無半套狀態殘留。

## Assumptions

- 排序為**全域單一清單**（所有商品共用一條順序），非依分類各自排序。
- 排序為管理端功能；顧客端的實際呈現由外部顧客 App 負責（不在本 repo 範圍），但其可讀取本系統儲存的順序。
- 低併發情境（少數管理員），併發衝突以後寫覆蓋處理即可，無需鎖定或版本控管。
- 既有商品的初始順序以目前的建立先後（識別碼遞增）為基準。
