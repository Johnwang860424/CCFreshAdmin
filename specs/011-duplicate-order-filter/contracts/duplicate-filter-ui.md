# UI 行為契約: 重複下訂快速篩選（訂單管理頁）

本功能無 API／schema 變更；對外契約即訂單管理頁（`app/(admin)/orders/page.tsx`）的 UI 行為。

## C1. 判定鍵（2026-07-13 第二次修訂：僅姓名）

| 情境 | 鍵 |
|------|-----|
| 姓名去除頭尾空白後非空 | 該姓名字串（如 `王小明 ` → `王小明`） |
| 姓名去頭尾空白後為空（防禦，姓名必填） | 無鍵——不參與重複判定 |

- 姓名相同、電話不同（或無電話）→ 同一鍵，算重複（只看姓名；同名不同人的誤標為已裁決取捨）。
- 電話相同、姓名不同 → **不**算重複（電話完全不參與比對）。
- 僅去頭尾空白：姓名內部空白/全形差異視為不同人，不做模糊比對。

## C2. 重複判定

- 母體＝目前路線視圖載入的**全部**訂單（含「未分路線」「宅配」視圖），與搜尋字串、開關狀態無關。
- 同一鍵出現 > 1 筆 → 該鍵下**每一筆**皆為重複下訂（3 筆以上全數計入）。
- 資料重載（切換路線／重新整理／刪單／出貨）後即重算。

## C3. 篩選開關

- 位置：actions 列，搜尋框旁。
- 形式：Checkbox，文字「只看重複下訂（N 筆）」，N＝母體中重複下訂的**訂單筆數**。
- N=0：disabled，顯示（0 筆）。
- 開啟後：列表＝「重複下訂 ∩ 既有搜尋條件」；同鍵訂單相鄰排列（組間依組首筆於原清單的位置、組內維持原相對順序）。
- 關閉後：完全回復既有排序與範圍。
- 未選路線：維持既有「請先選擇路線」空狀態，開關無資料可作用。

## C4. 下游一致性（開啟篩選時）

以下全部只計入篩選後可見的訂單：

- 路線總金額卡（金額與「篩選結果共 N 筆」）
- 各站點總金額統計
- 表頭全選（勾選範圍＝篩選結果全部分頁；取消全選只解除篩選範圍內的勾選）

勾選出貨／勾選匯出的作用對象＝**所有被勾選的訂單**——含開啟篩選前已勾選、目前被篩選隱藏者（沿用既有 `preserveSelectedRowKeys` 與搜尋篩選的跨篩選保留語意）；端點與參數不變。

## C5. 重複標示

- 重複下訂的訂單於「客戶」欄位姓名後顯示橙色（orange）「重複」Tag。
- 恆常顯示：不論開關是否開啟、不論搜尋字串為何。
- 與「來源」欄既有 Tag（網站/FB/Line）及勾選選中態可同時存在且可區分（欄位不同、色系不同）。
- 非重複訂單的客戶欄僅顯示姓名，無任何標籤。

## C6. 不變式（迴歸保證）

- `rowKey`／勾選 key 仍為訂單 `id`；展開列、分頁、勾選跨頁保留（`preserveSelectedRowKeys`）行為不變。
- 切換路線清空勾選的既有行為不變。
- 未開啟開關且無重複訂單時，頁面行為與現狀完全相同。
- 出貨／匯出／刪單／編輯訂單的 API 呼叫與 payload 零改動。
