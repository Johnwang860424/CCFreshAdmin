# Feature Specification: 重複下訂快速篩選

**Feature Branch**: `011-duplicate-order-filter`

**Created**: 2026-07-13

**Status**: Draft

**Input**: User description: "訂單管理頁新增「重複下訂快速篩選」：消費者有時會重複下訂，管理員需要在目前選定的路線視圖內快速篩選出重複下訂的訂單。判定方式：以客戶電話為優先 key（去除空白），無電話時退回以客戶姓名判定；同一 key 在目前路線視圖出現超過一筆即視為重複下訂。純前端篩選（方案 A，不跨路線、不動 DB/API）：在搜尋框旁提供「只看重複下訂」開關並顯示重複筆數，開啟後與既有搜尋條件 AND 疊加，總金額卡、全選、勾選出貨/匯出等既有功能自動套用篩選結果；篩選後同一客戶的訂單相鄰排列。另外在表格列上直接以背景色標記重複下訂的訂單，即使未開啟篩選也一眼可見。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一鍵篩選出重複下訂的訂單 (Priority: P1)

管理員在訂單管理頁選定路線（含「未分路線」「宅配」視圖）後，於搜尋框旁看到「只看重複下訂」開關，開關上同時顯示目前視圖內重複下訂的訂單筆數。開啟後列表只剩重複下訂的訂單，且同一位客戶的訂單相鄰排列，方便逐一比對後刪除多餘訂單或合併品項；既有的搜尋框、總金額統計、全選與勾選出貨／匯出，全部照常作用在篩選後的結果上。

**Why this priority**: 這是本功能的核心訴求——消費者重複下訂時，管理員要能「快速篩選出來」處理，不必逐頁肉眼比對。

**Independent Test**: 在某路線建立三筆訂單：甲（電話 0912345678）兩筆、乙一筆。選定該路線後開關顯示「2」；開啟後列表僅剩甲的兩筆且相鄰；總金額卡改顯示這兩筆的合計；關閉後回復全部三筆。

**Acceptance Scenarios**:

1. **Given** 路線視圖內有客戶甲（同電話）兩筆訂單與客戶乙一筆訂單，**When** 管理員開啟「只看重複下訂」，**Then** 列表僅顯示甲的兩筆訂單，且兩筆相鄰排列。
2. **Given** 同上，**When** 檢視開關旁的數字，**Then** 顯示重複下訂共 2 筆（以訂單筆數計，非客戶數）。
3. **Given** 篩選已開啟，**When** 管理員在搜尋框輸入關鍵字，**Then** 列表顯示「重複下訂 且 符合搜尋」的交集。
4. **Given** 篩選已開啟，**When** 檢視總金額卡與各站點統計，**Then** 金額與筆數僅計入篩選後的訂單。
5. **Given** 篩選已開啟，**When** 管理員使用表頭全選，**Then** 全選僅勾選篩選後可見的訂單；出貨／匯出作用於所有「被勾選」的訂單——若開啟篩選前已勾選其他訂單，沿用既有跨篩選保留勾選的語意，仍包含在內（與現行搜尋篩選行為一致）。
6. **Given** 兩筆訂單客戶姓名相同但電話不同（或其一無電話），**When** 判定重複，**Then** 兩筆皆視為重複下訂（僅比對姓名，電話不參與）。
7. **Given** 兩筆訂單姓名相同但其一頭尾帶空白（「王小明 」與「王小明」），**When** 判定重複，**Then** 視為同一人（去除頭尾空白後比對）。
8. **Given** 目前視圖內沒有任何重複下訂，**When** 管理員開啟篩選，**Then** 開關顯示 0 筆，列表顯示空狀態提示。

### User Story 2 - 未開篩選也能一眼看見重複訂單 (Priority: P2)

管理員瀏覽訂單列表（未開啟篩選）時，重複下訂的訂單在「客戶」欄位的姓名後面以醒目「重複」標籤標示，讓管理員在日常瀏覽或用搜尋框查單時，順帶就能發現某筆訂單其實是重複下訂。

**Why this priority**: 標記是被動提示，補足 US1 的主動篩選——管理員不必記得去開開關，重複情形自然浮現；但沒有它 US1 仍完整可用，故為 P2。

**Independent Test**: 建立一組重複訂單後不開篩選，該兩筆訂單的客戶欄即有「重複」標籤，其他訂單無標籤；用搜尋框縮小結果後標籤依然存在。

**Acceptance Scenarios**:

1. **Given** 路線視圖內有重複下訂的訂單，**When** 管理員未開啟篩選瀏覽列表，**Then** 重複下訂的每一筆訂單於客戶欄姓名後顯示「重複」標籤，非重複訂單無標籤。
2. **Given** 管理員在搜尋框輸入關鍵字使列表只剩部分訂單，**When** 其中含重複下訂的訂單，**Then** 該筆的「重複」標籤仍然顯示（重複判定不受搜尋字串影響）。
3. **Given** 管理員刪除了重複兩筆中的一筆並重新載入，**When** 檢視列表，**Then** 剩下那筆不再顯示標籤（該客戶只剩一筆）。

### Edge Cases

- **姓名相同但電話不同**：仍視為重複下訂（判定只看姓名）。同名不同人會被誤標——此為使用者裁決接受的已知取捨，管理員以電話/取貨點自行複核。
- **電話相同但姓名不同**：不視為重複（電話完全不參與判定）。
- **姓名內部空白或全形差異**：「王 小明」與「王小明」視為不同人——僅去除頭尾空白，不做內部正規化。
- **重複判定的母體**：以目前路線視圖載入的全部訂單為準，不受搜尋字串影響——搜尋只剩一筆時，該筆若在視圖內有重複同伴，仍應被標記。
- **宅配／未分路線視圖**：與一般路線視圖行為完全相同（同為「目前視圖內」判定）。
- **切換路線**：重複判定與筆數隨新視圖的訂單重新計算；比照既有勾選行為，切換路線時清空既有勾選。
- **三筆以上同客戶**：全部視為重複下訂、全部標記並計入筆數。
- **跨路線重複**（同客戶分別下訂到不同路線／宅配）：本功能不偵測，明確列為範圍外（見 Assumptions）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 以「客戶姓名去除頭尾空白後的字串」為每筆訂單的判定鍵；電話 MUST 不參與比對。
- **FR-002**: 系統 MUST 以「目前路線視圖載入的全部訂單」為母體判定重複：同一客戶識別鍵出現超過一筆時，該鍵下的每一筆訂單均為「重複下訂」。判定不受搜尋字串或篩選開關影響。
- **FR-003**: 訂單管理頁 MUST 在搜尋框旁提供「只看重複下訂」開關，並於開關處顯示目前視圖內重複下訂的訂單筆數（以訂單筆數計）。
- **FR-004**: 開啟篩選後，列表 MUST 僅顯示重複下訂的訂單，且與既有搜尋條件為 AND 疊加（兩者交集）。
- **FR-005**: 篩選結果 MUST 自動套用於所有吃同一份列表資料的既有功能：路線總金額卡、各站點統計、表頭全選、勾選出貨、勾選匯出、「篩選結果共 N 筆」計數。
- **FR-006**: 開啟篩選時，同一客戶識別鍵的訂單 MUST 相鄰排列（分組相鄰；未開啟篩選時維持既有排序）。
- **FR-007**: 重複下訂的訂單 MUST 於列表「客戶」欄位的姓名後以「重複」標籤標示，無論篩選開關是否開啟、無論是否輸入搜尋字串。
- **FR-008**: 訂單資料重新載入（重新整理、刪單、出貨、切換路線）後，重複判定、筆數與標記 MUST 隨新資料重新計算。
- **FR-009**: 未選定路線時（尚未查詢訂單），篩選開關 MUST 不產生作用或不可用，維持既有「請先選擇路線」空狀態。

### Key Entities

- **訂單（既有）**: 既有訂單資料，本功能唯讀取用其客戶姓名、電話與金額；不新增、不修改任何儲存欄位。
- **客戶識別鍵（推導值）**: 由電話（優先）或姓名即時推導的分組依據，僅存在於畫面計算過程，不落地儲存。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員自選定路線起，最多 1 次操作（開啟開關）即可看到僅含重複下訂訂單的清單，無需逐頁肉眼比對。
- **SC-002**: 判定準確性：電話相同（忽略空白差異）的訂單 100% 被標記為重複；皆無電話且姓名相同者 100% 被標記；不符合上述條件者 0% 被誤標。
- **SC-003**: 開啟篩選後，頁面上所有統計數字（總金額、筆數、站點小計）與可勾選範圍在同一次操作內即與篩選結果一致，無需另行重新整理。
- **SC-004**: 未開啟篩選時，管理員能在列表中直接辨識出每一筆重複下訂的訂單（視覺標記可辨識率 100%）。

## Assumptions

- **範圍限於單一路線視圖**：重複判定僅涵蓋目前選定視圖（路線／未分路線／宅配）內的訂單；跨路線、跨視圖的重複下訂不在本次範圍（未來若有需要，另案以後端彙整查詢支援）。
- **純前端實作**：不新增資料表欄位、不新增或修改任何後端查詢與端點；判定與篩選全部在既有已載入的列表資料上進行。
- **姓名比對為去除頭尾空白後的完全相符**：不做內部空白、全形/半形或別字正規化（不做模糊比對）；電話完全不參與判定。
- **「重複下訂」不代表必然要刪除**：本功能只負責找出與呈現，後續處置（刪除多餘訂單、編輯合併品項）沿用既有訂單編輯／刪除功能，不新增自動合併或自動刪除行為。
- **篩選開關狀態於切換路線後保留**：筆數與結果一律隨新視圖重算，正確性不受影響；勾選則比照既有行為於切換時清空。
