# Quickstart 驗證指南: 重複下訂快速篩選

## 前置

1. `.env.local` 齊備（`DATABASE_URL`、Auth、Cloudinary 等，見 `.env.local.example`）。
2. `npm run dev` 啟動，以允許清單內的 Google 帳號登入。
3. 準備測試資料（可用訂單頁「新增訂單」直接建立，事後刪除）：於**同一路線**的取貨點建立——
   - 甲：2 筆，**同姓名**、電話不同（驗證只看姓名，電話不影響）
   - 乙：1 筆，獨特姓名
   - 丙：2 筆，姓名同為「王小明」、皆不填電話（同名即算重複，與有無電話無關）
   - 丁、戊：各 1 筆，**姓名不同**但電話相同（驗證電話不參與判定 → 不算重複）

## 驗證場景

對照 [spec.md](./spec.md) 驗收場景與 [contracts/duplicate-filter-ui.md](./contracts/duplicate-filter-ui.md)：

### A. 判定與標示（US2 / C1 / C2 / C5）

1. 選定該路線 → 甲的 2 筆與丙的 2 筆在客戶欄姓名後有橙色「重複」標籤；乙、丁、戊無標籤（丁戊同電話但姓名不同）。
2. 搜尋框輸入甲的姓名使列表只剩甲 → 標籤仍在（判定母體不受搜尋影響）。

### B. 篩選開關（US1 / C3）

1. 開關顯示「只看重複下訂（4 筆）」（甲 2＋丙 2）。
2. 開啟 → 列表僅剩 4 筆，甲兩筆相鄰、丙兩筆相鄰。
3. 開啟狀態下輸入搜尋字串 → 顯示交集。
4. 關閉 → 回復全部訂單與原排序。

### C. 下游一致性（C4）

1. 開啟篩選 → 總金額卡金額＝4 筆合計、「篩選結果共 4 筆」；站點統計只含這 4 筆。
2. 表頭全選 → 僅勾選 4 筆；執行「匯出選取」→ CSV 僅含這 4 筆。
3. （可選）勾選其中 1 筆執行出貨 → 僅該筆消失。

### D. 重算（FR-008 / C2）

1. 刪除甲其中 1 筆 → 重新載入後甲剩 1 筆，標籤消失，開關筆數變「（2 筆）」（只剩丙）。
2. 切換到別的路線再切回 → 筆數與標記隨各視圖資料正確重算；切換時勾選被清空（既有行為）。
3. 「宅配」視圖建 2 筆同電話訂單 → 行為與一般路線一致。

### E. 邊界

1. 某路線無任何重複 → 開關顯示（0 筆）且 disabled。
2. 未選路線 → 維持「請先選擇路線」空狀態。
3. 姓名頭尾帶空白的訂單（「王小明 」）→ 去頭尾空白後與「王小明」併組判為重複。

## 完成門檻

- `npm run lint` 通過。
- `npm run build` 通過（TS strict）。
- 上述 A–E 全數符合預期。
- 清除測試訂單，確認無標記殘留、既有頁面行為（分頁、展開、勾選）無迴歸。
