# Quickstart — 取貨號碼英數格式驗證

## 前置

- `.env.local` 齊備（DATABASE_URL、AUTH_*、ALLOWED_EMAILS）。
- `npm run dev` 啟動、以允許清單帳號登入。
- 至少兩個自取站點（記下其 id 順序無妨，代碼由 id 換算：id 1→A、id 2→B…）。

## 場景 1 — 跨站點唯一與新格式（US1／FR-001~004）

1. 於「訂單管理」用「新增訂單」在站點甲、站點乙各建 1 筆自取訂單。
2. **預期**：兩筆取貨號皆為「英文＋數字」（例如 `A6`、`B3`——數字接續各站既有序列）；兩筆英文代碼不同。
3. 在站點甲再建 1 筆。**預期**：同字母、數字 +1。

## 場景 2 — 清單、搜尋、匯出一致（US2／FR-005~006）

1. 訂單管理頁檢視取貨號欄。**預期**：自取全為新格式；既有舊訂單也直接以新格式顯示（不重編，FR-009）。
2. 搜尋框輸入某筆的號碼（小寫也試，如 `a6`）。**預期**：命中該筆。
3. 勾選數筆跨站點訂單 →「匯出所選」；另對整組執行結單匯出。**預期**：兩份 xlsx 的「取貨號」欄皆為新格式且與畫面一致；表頭與欄序不變。

## 場景 3 — 宅配不受影響（FR-007）

1. 建 1 筆宅配訂單。**預期**：取貨號為純數字（宅配自身序列），無英文代碼；清單與匯出檔一致。

## 場景 4 — 出貨後歸 1（US3／FR-010）

1. 對某站點所屬分組執行出貨清除，再於該站建新訂單。
2. **預期**：號碼為「該站代碼＋1」（如 `A1`）；代碼字母不變。

## 場景 5 — 顧客端相容（FR-008，抽查）

1. （如可操作）由外部顧客端 App 下一筆自取單。
2. **預期**：下單成功；該筆在後台以新格式顯示。

## 靜態驗證

```powershell
npm run lint
npm run build
```

兩者皆須通過（憲法 Development Workflow）。
