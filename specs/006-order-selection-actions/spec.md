# Feature Specification: 訂單勾選出貨與匯出 CSV（跨頁選取）

**Feature Branch**: `006-order-selection-actions`

**Created**: 2026-07-02

**Status**: Draft

**Input**: User description: "訂單管理 每筆訂單最前面加入 checkbox，可以針對不特定的訂單出貨以及匯出 CSV，且可以跨頁選取"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 勾選任意訂單並出貨 (Priority: P1)

管理員在訂單管理頁面檢視某路線的訂單時，發現只有其中部分訂單需要出貨（例如客戶已確認、款項已收）。目前的「出貨」只能整組（整條路線／宅配／未分路線）一次清除，無法只針對挑選出的幾筆。管理員希望在每筆訂單最前面看到一個勾選框，勾選想處理的訂單後，一次將這些被勾選的訂單出貨（永久清除）。

**Why this priority**: 這是使用者提出的核心痛點——把「整組出貨」細化到「任意挑選出貨」。少了它，功能沒有意義；有了它即為可交付的 MVP。

**Independent Test**: 選定一條路線後，勾選其中 2 筆訂單，按「出貨選取」，確認僅那 2 筆被清除、其餘訂單保留，且勾選狀態在動作後清空。

**Acceptance Scenarios**:

1. **Given** 某路線有 5 筆訂單且皆未勾選，**When** 管理員勾選其中 2 筆並執行「出貨選取」並在確認視窗按確定，**Then** 系統永久清除該 2 筆訂單、其餘 3 筆保留，畫面刷新後勾選被清空。
2. **Given** 沒有任何訂單被勾選，**When** 管理員檢視操作列，**Then** 「出貨選取」與「匯出選取訂單」按鈕呈停用狀態（或按下時提示「請先勾選訂單」）。
3. **Given** 管理員已勾選數筆訂單，**When** 按下「出貨選取」，**Then** 系統先顯示確認視窗，列出將被清除的訂單筆數並警示此操作無法復原、建議先匯出備份，需再次確認才執行。

---

### User Story 2 - 勾選任意訂單並匯出 CSV (Priority: P1)

管理員希望先把挑選出來的訂單匯出成檔案備份（沿用現行依縣市分頁的 Excel 格式），再決定是否出貨。匯出只下載、不清除資料，可重複進行。

**Why this priority**: 現行流程強烈建議「出貨前先匯出備份」；若能出貨挑選訂單卻不能匯出相同挑選，備份就會與實際出貨範圍不一致。與 Story 1 同等關鍵。

**Independent Test**: 勾選 3 筆訂單，按「匯出選取訂單」，確認下載的檔案僅含那 3 筆、內容欄位與現行匯出一致，且資料未被清除、可再次匯出。

**Acceptance Scenarios**:

1. **Given** 管理員勾選 3 筆訂單，**When** 執行「匯出選取訂單」，**Then** 系統產生僅含該 3 筆訂單的檔案並下載，訂單資料保持不變。
2. **Given** 剛完成一次匯出，**When** 管理員未變更勾選再次匯出，**Then** 可再次成功下載相同內容（匯出可重複）。
3. **Given** 被勾選的訂單分屬不同縣市，**When** 匯出，**Then** 檔案沿用現行「依縣市分頁」規則，各縣市各自成一個工作表分頁。

---

### User Story 3 - 跨頁維持勾選狀態 (Priority: P2)

當某路線訂單筆數超過單頁顯示（表格分頁）時，管理員需要在第 1 頁勾幾筆、翻到第 2 頁再勾幾筆，最後一次對全部勾選的訂單出貨或匯出。翻頁不應清掉先前的勾選。

**Why this priority**: 是「跨頁選取」的明確需求，讓挑選在大量訂單時仍可用；但 Story 1/2 在單頁情境下已可獨立交付，故列為 P2。

**Independent Test**: 將分頁設為每頁 10 筆並確保有超過 10 筆訂單；在第 1 頁勾 2 筆、翻到第 2 頁勾 1 筆、翻回第 1 頁，確認先前 2 筆仍為勾選，總計 3 筆納入後續動作。

**Acceptance Scenarios**:

1. **Given** 訂單跨多個分頁，**When** 管理員在不同分頁分別勾選訂單並翻頁往返，**Then** 已勾選的訂單在翻頁後仍保持勾選。
2. **Given** 已跨頁勾選數筆，**When** 執行「出貨選取」或「匯出選取訂單」，**Then** 動作涵蓋所有分頁上被勾選的訂單，而不只是目前顯示頁。
3. **Given** 已跨頁勾選數筆，**When** 畫面顯示已選取數量，**Then** 顯示的數量等於所有分頁被勾選的總筆數。

---

### Edge Cases

- 被勾選的某筆訂單在動作執行前已被他處刪除或已出貨：系統應忽略已不存在者、對仍存在者完成動作，並回報實際處理筆數（不因單筆失效而整批失敗）。
- 目前「於結果內篩選」搜尋框縮小了可見清單：勾選狀態針對訂單本身，不因篩選字變更而遺失；被篩掉而看不見的已勾選訂單仍計入後續動作（並於已選取數量中呈現）。
- 切換「選擇路線」下拉載入另一組訂單資料時：先前勾選一律清空，避免對非目前路線的訂單誤操作（FR-011）。
- 勾選 0 筆時執行動作：按鈕停用或提示，不送出。
- 匯出／出貨進行中：按鈕顯示載入中並避免重複送出；出貨採整批確認後執行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 訂單管理表格 MUST 在每一列最前面提供一個勾選框，讓管理員可勾選／取消勾選該筆訂單；並提供「全選目前頁」的表頭勾選框。
- **FR-002**: 系統 MUST 顯示目前已勾選的訂單總筆數，且該數字涵蓋所有分頁的勾選（非僅目前顯示頁）。
- **FR-003**: 管理員 MUST 能對「目前已勾選的訂單集合」執行出貨，永久清除這些訂單（沿用現行出貨即刪除、無法復原的語意）。
- **FR-004**: 管理員 MUST 能對「目前已勾選的訂單集合」匯出 CSV／Excel 檔；匯出只下載、不清除資料且可重複。
- **FR-005**: 匯出的檔案 MUST 沿用現行匯出的欄位與「依縣市分頁」規則（宅配、無縣市者各自成頁），僅將範圍限縮為被勾選的訂單。
- **FR-006**: 執行「出貨選取」前，系統 MUST 顯示確認視窗，載明將清除的訂單筆數、警示無法復原並建議先匯出備份，經再次確認才執行。
- **FR-007**: 當已勾選 0 筆時，「出貨選取」與「匯出選取訂單」MUST 無法送出（按鈕停用或明確提示）。
- **FR-008**: 勾選狀態 MUST 在表格分頁切換（翻頁、回上一頁）之間保持不遺失。
- **FR-009**: 出貨成功後，系統 MUST 刷新訂單清單與相關計數，並清空勾選狀態；匯出成功後 MUST 維持勾選（匯出為唯讀、可重複），不需刷新清單。
- **FR-010**: 當被勾選的訂單於執行時部分已不存在（他處已刪除／已出貨），系統 MUST 對仍存在者完成動作、忽略失效者，並回報實際處理筆數，不因此整批失敗。
- **FR-011**: 勾選範圍 MUST 限定於目前選定的單一路線視圖：切換「選擇路線」下拉載入另一組訂單資料時，系統 MUST 清空先前的勾選；出貨與匯出僅作用於目前路線中被勾選的訂單，不跨路線累積。
- **FR-012**: 既有的「出貨 / 匯出 CSV」整組操作（依路線／宅配／未分路線）MUST 保留，與新的勾選式操作並存，兩者互不影響。

### Key Entities *(include if data involved)*

- **訂單 (Order)**: 既有實體。此功能新增「是否被勾選」的畫面選取狀態（不落地儲存），並以訂單的唯一識別（id）作為勾選、出貨、匯出的依據。
- **勾選集合 (Selection Set)**: 管理員目前選取之訂單 id 的集合，存在於畫面狀態、跨分頁維持，作為「出貨選取」與「匯出選取訂單」的作用範圍。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員可只出貨一組訂單中的任意子集，被清除的訂單筆數與勾選數完全一致，未勾選者 100% 保留。
- **SC-002**: 管理員可在 3 個操作內（勾選→按匯出→取得檔案）完成挑選訂單的 CSV 匯出，且檔案內容僅含被勾選訂單。
- **SC-003**: 在超過一頁的訂單清單中跨頁勾選後，已選取筆數與最終出貨／匯出筆數與實際勾選數一致（跨頁不遺失、不重複）。
- **SC-004**: 未勾選任何訂單時，無法誤觸執行出貨或匯出（0 筆時不送出）。
- **SC-005**: 匯出挑選訂單的檔案格式（欄位、依縣市分頁）與既有整組匯出一致，既有整組出貨／匯出流程不受影響仍可正常使用。

## Assumptions

- 沿用現行「出貨即永久刪除、無法復原」語意；本功能只改變作用範圍（整組 → 任意勾選），不改變出貨後果。
- 匯出檔案格式沿用現行 xlsx（依縣市分頁、既有欄位表頭），不新增或調整欄位。
- 「跨頁」指同一路線視圖下訂單表格的分頁切換；勾選狀態以訂單唯一識別維持，切換路線則清空。
- 「於結果內篩選」搜尋只影響可見列，不清除已勾選訂單；已勾選但被篩掉者仍計入動作。
- 既有依路線／宅配／未分路線的整組出貨與匯出入口保留（FR-012）。
- 出貨與匯出皆屬變更／敏感操作，沿用現行僅登入管理員可執行的授權要求。
