# Quickstart 驗證指南: 商品庫存管理與防止超賣

**Plan**: [plan.md](./plan.md) | **Contract**: [contracts/product-stock.md](./contracts/product-stock.md)

## 前置

1. 於 Neon SQL Editor 執行 `db/migrations/007_add_product_stock.sql`（一次）。
2. `.env.local` 齊備（既有變數即可，無新增）。
3. `npm run dev`，以 allowlist 帳號登入後台。

## 靜態檢查

```bash
npm run lint    # 必須通過（憲法）
npm run build   # 型別檢查必須通過
```

## US1: 商品管理頁維護庫存

1. 商品管理 → 新增商品，庫存填 `10` → 儲存成功，列表「庫存」欄顯示 10。
2. 編輯該商品，庫存改 `5` → 列表同步顯示 5。
3. 庫存輸入 `-3`、`2.5` → 表單阻擋（非負整數提示）。
4. 庫存清空後儲存 → 列表顯示「不限量」。
5. 既有（未動過的）商品 → 列表顯示「不限量」（migration 後預設 NULL）。
6. 把某商品庫存改 `0` → 列表顯示紅色「售完」。

## US2: 新增訂單防超賣

前置：商品甲庫存設 `3`；商品乙留空（不限量）。

1. 訂單管理 → 新增訂單，甲 ×2 → 成立；商品列表甲剩餘 1。
2. 再新增訂單，甲 ×2 → 被拒，訊息含「「甲」庫存不足（剩餘 1）」；甲庫存仍 1。
3. 一筆訂單含 甲 ×1（足）＋另一庫存不足商品 → 整筆被拒，兩商品庫存皆不變。
4. 訂單含 乙 ×99（不限量）→ 照常成立。
5. 甲庫存 0 後 → 新增訂單的商品選單中甲顯示「售完」且不可選。

### 併發驗證（SC-001）

甲庫存設 `1`，同時發兩筆各訂 1 件的請求（`ORDER_BODY` 為合法的新增訂單 JSON，兩份相同；`COOKIE` 取自已登入瀏覽器）：

```bash
for i in 1 2; do
  curl -s -X POST http://localhost:3000/api/orders \
    -H "Content-Type: application/json" -H "Cookie: $COOKIE" \
    -d "$ORDER_BODY" &
done; wait
```

預期：恰一筆 `success`、另一筆 400 庫存不足；甲庫存為 0（不為 -1、無兩筆皆成立）。

## US3: 編輯／刪除訂單同步調整

前置：甲庫存 `5`，成立含 甲 ×3 的訂單（剩 2）。

1. 編輯訂單 甲 3→4 → 成功，剩 1（僅扣淨增 1）。
2. 編輯訂單 甲 4→6（剩 1 不足淨增 2）→ 整次編輯被拒，訂單與庫存不變。
3. 編輯訂單 甲 4→1 → 成功，回補 3、剩 4。
4. 刪除整筆訂單 → 回補、剩 5。
5. 建含甲訂單後對該群組「出貨」→ 訂單清除、庫存**不**回補。
6. 選取該訂單用「選取出貨」→ 同樣不回補。

## 快取鮮度（D7）

任一訂單成立/編輯/刪除後，重新整理商品管理頁 → 「庫存」欄立即為最新值（不需等快取過期）。

## 相容性

- 顧客端 App 照常下單（或直接對 DB INSERT 模擬）→ 成功、不扣庫存（FR-010）。
- 商品 API `GET /api/products` 回傳含 `stock` 欄位，舊消費端不受影響（additive）。
