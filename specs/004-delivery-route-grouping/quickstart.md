# Quickstart 驗證指南: 後台依「送貨路線」分組

驗證本功能端到端可運作。對應 spec 的 6 條驗收條件與 SC-001~SC-007。

## 前置

1. 套用 migration（research/data-model）至 Neon：建立 `routes` 表、`pickup_spots.route_id` 欄位，並更新 `db/schema.sql`。
2. 既有 `pickup_spots` 列的 `route_id` 應為 `NULL`（落入未分路線）。
3. `npm run dev`，以允許清單（`ALLOWED_EMAILS`）內帳號登入後台。
4. 建議備有：跨多縣市的數個取貨點、各取貨點若干自取訂單、至少一筆宅配訂單（由前台/既有資料提供）。

## 驗收流程

### A. 路線管理（驗收 1、2 / FR-001~005）
1. 側邊欄出現「路線管理」→ 進入。
2. 新增「A 線」；再新增同名「A 線」→ 應被拒並提示**名稱重複**。
3. 改名「A 線」→「北區 A 線」→ 成功。
4. 先不指派取貨點，刪除一條空路線 → 成功。
5. （見 B 指派後）對仍有取貨點的路線按刪除 → 應**失敗並提示「仍有 N 個取貨點」**；移除/改派全部取貨點後再刪 → 成功。

### B. 取貨點歸屬與排序（驗收 1、6 / FR-006~009）
1. 自取點管理頁：**維持以「縣市」分 tab**（此排序供前台顧客選點），列表有「所屬路線」欄（**唯讀顯示**，modal 內無路線欄位）。
2. **路線管理頁**：「自取點」欄以 Tag 列出各路線目前的自取點；點「北區 A 線」的**編輯** → modal 內可改名＋以**多選**把數個**跨縣市**取貨點指派給此路線（已屬其他路線的取貨點顯示「（已屬 …）」且不可選＝不可重複指派）；存檔後這些取貨點即出現在「北區 A 線」的 Tag 中、並從「未分路線」移除。
3. 自取點管理頁某縣市 tab 內拖拉排序取貨點 → 重新整理後順序保留（縣市內排序、供前台選點，不受路線影響）。
4. 未指定路線的取貨點，其「所屬路線」欄顯示「未分路線」，在路線管理頁的「未分路線」列可見，並在後台統計/篩選/結單歸入「未分路線」。

### C. 路線訂單統計（驗收 3 / FR-010~013）
1. 統計頁標題為「**路線訂單統計**」；提供路線下拉（全部路線 / 各路線 / 未分路線）＋日期區間（起、訖兩欄，**預設皆今天**）。
2. 下拉選「北區 A 線」、日期維持今天 → 交叉表**列＝該路線各取貨點（縣市+鄉鎮）**、欄＝商品數量，最後附**各商品總量**；取貨點列序符合縣市內拖拉順序；**商品欄順序依商品管理的顯示順序（`products.sort_order`）**。
3. **不選路線（全部路線）、日期維持今天** → 列＝今天有自取訂單的**所有取貨點（跨路線）**，依 `sort_order` 排序；附各商品總量。
4. 將日期區間改為涵蓋多天 → 統計納入該區間（含起訖兩端、台北時區）所有自取訂單。
5. 匯出 CSV → 內容與畫面一致（反映目前路線/日期條件）、可開啟。
6. 下拉選「未分路線」→ 同樣可顯示與匯出；選一條**無訂單**的路線 → 顯示空表（不報錯）。
7. 清空日期且未選路線 → 提示「請至少指定路線或日期」，不執行查詢。

### D. 訂單管理篩選（驗收 4 / FR-014~016）
1. 篩選下拉維度為**路線**，含具體路線、「未分路線」、「宅配」。
2. 選「北區 A 線」→ 僅列出該路線上各取貨點訂單。
3. 選「未分路線」→ 列出未指派路線取貨點的訂單；選「宅配」→ 僅宅配訂單。
4. 展開明細、結果內文字搜尋 → 行為與改版前一致。

### E. 路線結單（驗收 5、6 / FR-017~021）
1. 結單視窗的可結單分組以**路線**列出（+未分路線 +宅配），各顯示筆數。
2. 對「北區 A 線」結單 → 下載**一份** CSV，涵蓋該路線**所有取貨點**訂單；CSV「取貨地點」欄以**縣市+地點**區分不同點（跨縣市同名鄉鎮亦可區分）；檔名含「北區 A 線」。
3. 僅在 CSV **下載成功後**，該路線訂單才被清除；模擬下載失敗（取消/中斷）→ 訂單**不被清除**。
4. 對「未分路線」「宅配」各自結單 → 互不混入。
5. 結單後同取貨點的 `pickup_number` 規則不變（各點各自從 1 起算）。

### F. 導覽與文案（FR-022/023）
- 側邊欄有「路線管理」；統計選單文字為「路線訂單統計」；訂單頁「選擇縣市」等文案改為路線。

## 收尾檢查
- `npm run lint` 通過。
- `npm run build` 型別檢查通過。
- 前台顧客端選點與訂單寫入未受影響（FR-024 / SC-007）—— 本 repo 無改動前台選點/寫入碼，僅 `revalidateCache("routes"/"pickup-spots")` 通知。
